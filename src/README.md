# Tech Plan

## Platform and delivery

- **Stack:** Phaser 4, TypeScript and Vite.
- **Hosting:** Cloudflare Workers static assets, no Worker script (`wrangler.jsonc`).
- **Targets:** landscape phone browsers with on-screen touch controls, and desktop browsers with a keyboard.
- **Tooling:** Node 24, Vitest, ESLint with the shared house rules, Prettier, markdownlint, husky + lint-staged, Dependabot, and the Test and AI attributions workflows.

## Architecture

- **Atlas:** a production build packs every PNG `public/art/manifest.json` lists (sprites, fonts, tilesets and backdrops) whole into atlas pages, each image's edge pixels repeated 1 px around it, written as lossless WebP (libwebp's `-lossless -exact`, every pixel kept) under `/assets/art/` with a content hash in the name (`src/tools/atlas/`); the atlas manifest that maps each art key and frame to its page and rect is built into the game's code. `BootScene` loads the pages and gives each key a texture that shares its page's source (`src/scenes/atlasArt.ts`), so the page uploads to the GPU once, batches draw from one texture, and code that names a key and its frames works as with the key's own files; each font is made from its `.fnt` and its frame there. The dev server has no atlas and loads each file on its own. Art's files stay as art writes them.
- **Back:** `src/pwa/backNavigation.ts` catches back, in a browser tab and the installed app, with a CloseWatcher where the browser has one and otherwise a guard history entry pushed from the player's first key or tap, and dispatches `back-pressed` on window for `PauseScene`. Quit goes back past the game to the page before it, or with none closes the window where the browser allows it. Firefox for Android's installed app keeps the browser's own back.
- **Crash screen:** `src/main.ts` first imports `src/crash/install.ts`, which installs the kit's crash screen in art's palette with the words in `src/data/text.ts`; it pauses the game on the first uncaught error. `?dev=1` adds the error's details. The build label's version and commit come from Vite's `define` in `vite.config.ts`, the commit reading `dev` without git.
- **Game data:** `src/data/types.ts` holds the shapes; every other file in `src/data/` holds gameplay's values, with the words the player reads in `text.ts`.
- **Installed app:** the home page's Install button (`src/homePage/main.ts`, on the kit's install flow) shows the browser's install prompt, or the steps for a browser that installs only from its own menu (iOS, Firefox for Android), and hides once installed. The web app manifest starts the app on `/play/`, which the service worker precaches, full screen and locked to landscape. In the app the game page has no nav bar, so no link leaves the game. The game page shows the build label in its top right corner. The screen stays on during play, and sleeps as usual while the pause card is open or the page is hidden; the installed app asks the browser once per launch to keep its storage.
- **Levels:** a level is played from its `LevelPlan` in tiles (`src/data/types.ts`), converted once to pixels for the rules: areas of terrain and placed instances. Each instance is a character (`src/data/characters.ts`: its art, animations by state, size, words and quirks) on an archetype (`src/data/archetypes.ts`: its collision and default motion, reaction and interaction), resolved once at load into a flat object, an instance's overrides over its character's tuning over its archetype; carried-choice flags place or leave out an instance. Use at a door fades to another area; Use at the exit clears the level. A level's start is its only checkpoint, and each restart is a new attempt that rolls the objects' random motion afresh from the level's seed (`?seed=<n>` fixes it). Level 1 (`src/data/level1.ts`) plays first, then the test levels in `src/data/levels.ts`, looping; `?level=<n>` (from 1) starts at one. An area with a tileset draws its terrain from art's tiles by each run's look, and each object by its art key: a tile or piece of that tileset, a backdrop (bottom-left anchored, a repeating one tiled across the object's width), a sprite, or a flat placeholder for art named `placeholder-*`.
- **Offline play:** the build writes `/sw.js` (the kit's service worker with `src/pwa/cachePolicy.ts`), precaching `/play/`, what it loads and links, the atlas pages, and the manifest, data, font and tileset descriptions under `/art/`. `src/pwa/` registers it in production: at once on a page a version controls, and on a first visit once the level shows, so the precache does not compete with the game's own downloads (`registerWhenDue`). A new version's install copies the hashed files the last one stored and fetches the rest. The game loads while a fresh load checks for a newer version; `BootScene` holds only the level for it (`launchReady`, up to 4 seconds). A newer version takes over before the player interacts (a tap while the game loads counts), and after that the page's "Update available" toast offers it while the level is in front, never under the pause card or the turn-sideways notice. It checks on each load and whenever the page comes back into view, at most once a minute.
- **Pause card:** `PauseScene` runs beside `LevelScene` and draws over it: the pause button in the top-left corner, and the card (`src/layout/pauseCard.ts`) that it, P, Escape and back open. The card pauses the level over a dim of it read back from the canvas and redrawn two steps down each colour's ramp (palette.json's `dim2`, `src/view/dim.ts`), read once with the touch buttons hidden and once shown so the Touch controls row updates the view behind the card. Resume, the close X, P, Escape and back close it; Quit leaves the game. While the level is not in play (under the card, and while `BootScene` loads) the game draws on every Nth display frame, about 60 a second, each draw advancing by the skipped frames' time (the kit's `clock/phaser/capFrameRate`); in play it draws every display frame. The Touch controls setting is kept in `localStorage` (`src/settings/touchControls.ts`).
- **Phaser boundary:** only `src/scenes/` and `src/main.ts` import Phaser or a scene, enforced by ESLint's `no-restricted-imports`. Logic, layout and data are Phaser-free, so they unit-test without a renderer.
- **Phaser build:** the game runs on WebGL alone, with no sound. A production build bundles Phaser from its source without the namespaces the game does not use, the Canvas renderer or the sound manager (`PHASER_BUILD` in `src/tools/phaserBuild.ts`, built by the kit's `build/vite/phaserBuildPlugin`; its test fails when the game uses something it leaves out), in its own hashed chunk, so an update that changes only game code keeps Phaser's file. The dev server and Vitest load the package's own bundle.
- **Scenes:** `BootScene` runs first: it loads everything `public/art/manifest.json` lists and makes an animation of each sprite tag, keyed `<sprite>:<tag>`, with the tag's frames and durations from the sprite's Aseprite export. A tag the sprite's manifest entry lists in `once` plays once and holds its last frame; every other tag loops.
- **Security headers:** the build writes `dist/_headers` from `src/headers/securityPolicy.ts`: a Content-Security-Policy per page with its inline blocks hashed, and a year's caching for hashed build output under `/assets/`.
- **Shared kit:** `@andornaut/game-kit` is a committed copy at `vendor/game-kit/`, synced by game-kit's `scripts/sync-into.sh` with its source commit in `vendor/game-kit/KIT_COMMIT`, and changed only at its source.
- **Test helpers:** `src/testing/` is importable only from tests.
- **View:** `src/view/` picks each sprite's tag and whole-pixel position from the game state, Phaser-free, so the scenes only draw what it picks.

## Remaining for the first build

- The game data files, and the export to `shared/export/` that art's tools read.
- Workers Builds deploys on push to `main`.
