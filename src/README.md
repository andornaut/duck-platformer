# Tech Plan

## Platform and delivery

- **Stack:** Phaser 4, TypeScript and Vite.
- **Hosting:** Cloudflare Workers static assets, no Worker script (`wrangler.jsonc`).
- **Targets:** landscape phone browsers with on-screen touch controls, and desktop browsers with a keyboard.
- **Tooling:** Node 24, Vitest, ESLint with the shared house rules, Prettier, markdownlint, husky + lint-staged, Dependabot, and the Test and AI attributions workflows.

## Architecture

- **Atlas:** a production build packs every PNG `public/art/manifest.json` lists (sprites, fonts, tilesets and backdrops) whole into atlas pages, each image's edge pixels repeated 1 px around it, written as lossless WebP with every pixel kept (the kit's `art/webp`) under `/assets/art/` with a content hash in the name (`src/tools/atlas/`); the atlas manifest that maps each art key and frame to its page and rect is built into the game's code. `BootScene` loads the pages and gives each key a texture that shares its page's source (`src/scenes/atlasArt.ts`), so the page uploads to the GPU once, batches draw from one texture, and code that names a key and its frames works as with the key's own files; each font is made from its `.fnt` and its frame there. The dev server has no atlas and loads each file on its own. Art's files stay as art writes them.
- **Back:** the kit's `pwa/backNavigation`, set up in `src/pwa/index.ts`, catches back, in a browser tab and the installed app, with a CloseWatcher where the browser has one and otherwise a guard history entry pushed from the player's first key or tap, and dispatches `back-pressed` on window for `PauseScene` and `StartScene`. Firefox for Android's installed app keeps the browser's own back.
- **Behaviour patterns:** `src/data/behaviours.ts` composes reusable state graphs for animals and moving props. A character selects a plan and an instance can replace it with a complete plan. Data names states, animation tags, move or wait primitives, entry heading capture and ordered transition conditions; the executor in `src/rules/behaviour.ts` handles either axis without character-specific sequencing. The antagonist and park boat use the same executor. Spatial values resolve from tiles to pixels when the zone loads, while durations remain seconds. Collision and interaction stay separate. Scene-associated patterns start inactive, activate after their conversation finishes and reset on each attempt.
- **Crash screen:** `src/main.ts` first imports `src/crash/install.ts`, which installs the kit's crash screen in art's palette with the words in `src/data/text.ts`; it pauses the game on the first uncaught error. `?dev=1` adds the error's details. The build label's version and commit come from Vite's `define` in `vite.config.ts`, the commit reading `dev` without git.
- **Death:** a failed attempt freezes the world and camera while the duck recoils, falls onto frozen support, squashes on impact and makes a small upward bounce into a seated rest. Void falls use a visible fallback inside the frozen viewport. The required `DeathScene` card then holds indefinitely, showing the zone name, numbered stage name, current-attempt percentage and cumulative active stage time in that order. Back to title preserves progress and the stage clock; Try again is the safe default and explicitly restarts the same layout with fresh object motion and dialogue. Outside taps, back and Escape cannot close the card. Held input is cleared across both transitions, and the pause controls stay inert. A two-pixel themed progress strip tracks this attempt, including backward movement; death presentation and modal time do not add to active stage time.
- **Dialogue:** conversations use `DialogueScene`, with plans and speakers in `src/data/dialogues.ts`, paragraph text in `TEXT.lines`, and names and controls in `TEXT.dialogue`. The fixed top panel shows one paragraph, at most three measured lines at the shared font size. Each speaker names a portrait side: the duck remains left and other speakers right; images are repositioned without mirroring. Secondary Skip and primary Continue share a footer below the panel. Fresh taps or non-repeating keys advance; Tab and arrows focus actions, and Enter or Space activates a focused action. Held touches and drags do not advance. Skip and the final paragraph open a required terminal choice when the plan defines one, otherwise end the conversation. `DialogueChoiceScene` uses the shared card and buttons, starts without a focused answer and cannot close through Skip, back, Escape or an outside tap. The zone remains held through the choice; only a selected option id is returned, with no actions or flags applied. All dialogue input is consumed. The dialogue stops before notifying the zone once through `dialogueClosed(selection?)`.
- **Entity mechanisms:** code defines mechanisms; typed data selects entity profiles, traits and tuning without dispatching on entity ids. Existing motion profiles map `ease` to the kit's `sineInOut` easing and other travelling profiles to `linear`; hop lift, phase and lazy seeded leg generation remain local. Reusable pure mechanisms belong in the shared kit when both games have compatible consumers. Changes preserve seeded randomness and replay.
- **Game data:** `src/data/types.ts` holds the shapes; every other file in `src/data/` holds gameplay's values, with the words the player reads in `text.ts`.
- **Installed app:** the home page's Install button (`src/homePage/main.ts`, on the kit's install flow) and the settings card's Install row (`src/pwa/installOffer.ts`) show the browser's install prompt, or the steps for a browser that installs only from its own menu (iOS, Firefox for Android), and hide once installed. The web app manifest starts the app on `/play/`, which the service worker precaches, full screen and locked to landscape. In the app the game page has no nav bar, so no link leaves the game. The screen stays on during play, and sleeps as usual while the pause card is open or the page is hidden; the installed app asks the browser once per launch to keep its storage.
- **Play view:** the canvas fills `#game` (Phaser's `Scale.EXPAND`), stretched by the most the base resolution takes on both axes, so where `#game` is wider or taller than 2:1 the canvas is too. Each scene's camera shows the game's base-resolution view at the canvas's top, centred across (`src/layout/playView.ts`, `src/scenes/playCamera.ts`), and the canvas's own bars, in the page's ink, fill the rest. Every control stays inside the view across, its drawn edge at least `CONTROL_EDGE` (8) from the edge it is placed against (`src/layout/playView.ts`): the pause button 8 in from the view's top and left; Jump 8 in from the view's right and `CONTROL_BOTTOM` (20) up from the canvas's bottom, with Use 100 above it and 85 in from the view's right, and the move hint level with Jump, as far in from the view's left as Use is from its right; so the bottom controls move into a bar below the game, and none into a bar beside it; the zone draws them in a second camera over the whole canvas, as the pause scene draws the pause button and the dim, and reads a touch's button through the same shift. The move hint (`src/view/moveHint.ts`) is a drawing with no press area: at rest it sits level with Jump, as far in from the view's left as Use is from its right; while a drag moves her, its ring sits where the drag began, held left or right the way she moves, with its knob up to 12 pixels left or right of the ring's centre the way the drag goes, and it returns to rest on release. The kit's `followFrameTurn` keeps the page no taller than the visible area (the visual viewport, not viewport units, which an installed app can size past the screen) and refits until the sizes settle on every signal that the visible area or the frame's turn may have changed, with a check four times a second while the page is visible for a fit or turn gone stale with no signal.
- **Press areas:** every button's press area is its drawn button grown on every side by a quarter of its shorter side, between 6 and 16 base pixels, and to at least 48 square about its centre (`HIT_RULE` in `src/layout/hitAreas.ts`). Use and Jump instead press within 100 of each centre: a clear circle of radius 63 (`TOUCH_CIRCLE_RADIUS`) and the move hint's radius of 37 beyond it, so a drag, which starts only off the buttons, draws the hint clear of each clear circle. The two are cut along the line midway between their centres, so they meet and never overlap, and Jump's reaches on into the screen's bottom-right corner, from its centre. Where two areas overlap, the button whose centre is nearer the press wins (`pressedArea`).
- **Zones:** a zone is played from its `ZonePlan` in tiles (`src/data/types.ts`), converted once to pixels for the rules: areas of terrain and placed instances. Each instance is a character (`src/data/characters.ts`: its art, animations by state, size, words and quirks) on an archetype (`src/data/archetypes.ts`: its collision and default motion, reaction and interaction), resolved once at load into a flat object, an instance's overrides over its character's tuning over its archetype; carried-choice flags place or leave out an instance. Use at a door shows its room (Rooms). Use reaches a door wherever her drawn frame (art's duck frame, placed over her collision box as the zone draws it) intersects the door's rect at all, which is its drawn rect; of two doors under her frame, the one whose centre is nearest hers opens (`doorAt` in `src/rules/zone.ts`). Her collision box reaching the last column of the area, at any height, clears the zone, which fades to black and leaves for the map; the zone walk clears it the same way and never presses Use. Her box reaching back into the first column (left of `backX`, the first column's right edge) ends the zone without clearing it (`turnedBack`): it fades to black the same way and opens the map with her on that zone, nothing completed and the save unchanged; through `?zone=` it plays the same zone again. Every zone's start, hand-built and every recipe's, sits clear of the first column, and held left from it she reaches that column, nothing in it stopping her (`src/data/zones.test.ts`), and the zone walk counts a try that takes her into it as failed, so neither ends a zone by turning back. A held key's repeats never press it, so a key held from before the zone resumes counts only once pressed again. A zone in `RECIPES` (`src/data/zones.ts`) is assembled from the chunks and themes in `src/data/chunks.ts` for a seed drawn afresh each time she enters it (`src/rules/assemble.ts`): its start chunk, a seeded run of its theme's chunks whose seams join, within its inclusive difficulty band regardless of position, each at most its `maxPerZone` and never one twice in a row, then its finish chunk, the whole within its length, searched with backtracking, with its events and doors in seeded slots (recorded in the plan): a filled door slot places the theme's door at its own size, centred across the slot (half a tile in where the widths differ by an odd count) and standing on its floor, leading to its room. Events are not built yet. Each chunk's contents move to its zone columns, its terrain looks map to the theme's tileset, and the theme's repeated backdrops span the zone; the result is an ordinary `ZonePlan`. The tests check every chunk against the chunk rules and the seam rule, assemble every recipe for 50 seeds, and walk each chunk alone and 5 seeds of each recipe (`src/data/chunks.test.ts`, `src/sim/chunkWalk.test.ts`), on small fixtures in `src/testing/chunks.ts` as well as gameplay's chunks. A zone's start is its only checkpoint, and each restart is a new attempt that rolls the objects' random motion afresh from the zone's seed (`?seed=<n>` fixes it).
- **Offline play:** the build writes `/sw.js` (the kit's service worker with `src/pwa/cachePolicy.ts`), precaching `/play/`, what it loads and links, the atlas pages, and the manifest, data, font and tileset descriptions under `/art/`. `src/pwa/` registers it in production: at once on a page a version controls, and on a first visit once the zone shows, so the precache does not compete with the game's own downloads (`registerWhenDue`). A new version's install copies the hashed files the last one stored and fetches the rest. The game loads while a fresh load checks for a newer version; `BootScene` holds only the zone for it (`launchReady`, up to 4 seconds). A newer version takes over before the player interacts (a tap while the game loads counts), and after that the page's "Update available" toast offers it while the zone is in front, never under the pause card or a room. It checks on each load and whenever the page comes back into view, at most once a minute. The icons `src/pwa/icons.ts` lists (the web app manifest's, and the pages' favicons and apple-touch-icon) are written again under content-hashed names under `/assets/` (`/assets/icons/`, and `/assets/art/` for the favicons), which the pages, the manifest and the precache name (the kit's `hashedIconsPlugin`), so a redrawn icon reaches an installed app and the hashed build output's year of caching covers them; `/manifest.webmanifest` keeps its name and is fetched network-first.
- **Map screen:** six themed destinations each group two ordered stage-node ids. The overview shows every regional miniature and name; locked markers use padlocks and unbuilt markers use question marks. Unbuilt stages have no playable plan and cannot be entered. Selecting a destination or Continue plays directly when exactly one stage is unlocked, and opens `StageSelectScene` only when multiple stages are unlocked. That closeable card lists unlocked stages, highlighting the latest reached stage with the primary style; earlier stages remain replayable. Closing, back, Escape and outside taps return to the map without selecting a stage. A new navigation press must focus an answer before keyboard activation, so opening input never selects one. Completed stage ids preserve unlocks across replay, and only the configured final apartment stage triggers celebration. Progress version 4 retains the same stage ids and remains compatible when another stage is built. Back to title remains secondary on the left; Continue remains primary on the right and the default map action. Tab selects footer actions, while Left/Right and A/D select unlocked destinations. Returning to the title preserves progress.
- **Modal cards:** every card over the game (the pause card, the settings card and its install steps, the restart card) shares one frame (`src/layout/cardFrame.ts`): art's `ui-settings-card` with no header, 368 wide at 176,88, its title in ink centred across it 8 down (`addCardTitle`), its close X at its top-right corner, and its first row or button 48 down. Text on its face is ink, the build label dslate. Its buttons come in two styles of one shape (`BUTTON` and `PRIMARY_BUTTON` in `src/scenes/cardParts.ts`, each with its label's colour): art's grey `ui-button` with an ink label, and the primary, `ui-button-primary`, dslate with a white label, which a card leads with. A setting row has no box: its dslate icon, its ink label and art's `ui-switch` (on or off), over a 352x48 press area. While a card shows, only the card responds (`catchModalTaps` in `src/scenes/modalTaps.ts`, on the kit's `input/phaser/catchOutsideTaps`, as dog-walker's panels): nothing under it does, the start screen's nav bar and the pause button included. A tap anywhere outside it, the bars beside the game's view included, only closes a card that can close, as its close X or back would; on a card with no close, a required choice, it does nothing at all (none has yet). A tap is a press that travels no further than `TOUCH.tapMaxDistance`. A press that lands outside is kept from the scenes under the card's, which stay inert, so each modal scene sits above every scene it covers in `main.ts`; the zone, paused under the pause card, never moves, jumps or uses on it. A new card gets all this by calling `catchModalTaps` with its rect and its controls' press areas. The celebration is a full screen, not a card, and has none.
- **Parallax:** decorative backdrops can set `parallax: { x, y }` on an instance or a theme backdrop, each factor from 0 (fixed in the view) to 1 (world speed), with both axes at 1 when omitted. Assembly preserves these factors and `ZoneScene` applies them as camera scroll factors while leaving the objects at their world positions. Repeated backdrops keep their full run width, so a layer spanning the zone still covers the view at either horizontal camera limit. Placed scenery retains its own art height and bottom anchor while the camera climbs. Collision, interaction, moving objects and non-backdrop art cannot use non-default factors.
- **Modal layout:** pause, settings, install steps, restart, dialogue choices and stage selection measure their text and actions through `src/layout/contentCard.ts`. Cards use 16px outer padding, 16px text lines, 4px stacked-row gaps and 8px between content groups. Action buttons remain 48px high and share the widest label width plus 32px within each group. Titles and close controls use measured header rectangles; font scale stays fixed.
- **Pause card:** `PauseScene` runs beside `ZoneScene` and draws over it: the pause button at the view's top-left corner, and the card (`src/layout/pauseCard.ts`) that it, P, Escape and back open, with three buttons of one shape, 352x48, stacked from its first row 52 apart, their labels centred: Resume, the primary, then Settings and Back to title. A change of the page frame's turn while the zone plays (the kit's `onChange`) opens it too. The card pauses the zone over a dim of it read back from the canvas and redrawn two steps down each colour's ramp (palette.json's `dim2`, `src/view/dim.ts`), read once for each mix of the two touch settings shown and hidden so the settings card's Move controls and Action buttons rows update the view behind it. Resume, the close X, P, Escape, back and a tap outside it close it; Back to title ends the zone for the start screen. Tab and the arrows move art's focus ring through Resume, Settings, Back to title and the close X, and Enter and Space press the focused one. While the zone is not in play (under the card, and while `BootScene` loads) the game draws on every Nth display frame, about 60 a second, each draw advancing by the skipped frames' time (the kit's `clock/phaser/capFrameRate`); in play it draws every display frame.
- **Phaser boundary:** only `src/scenes/` and `src/main.ts` import Phaser or a scene, enforced by ESLint's `no-restricted-imports`. Logic, layout and data are Phaser-free, so they unit-test without a renderer.
- **Phaser build:** the game runs on WebGL alone, with no sound. A production build bundles Phaser from its source without the namespaces the game does not use, the Canvas renderer or the sound manager (`PHASER_BUILD` in `src/tools/phaserBuild.ts`, built by the kit's `build/vite/phaserBuildPlugin`; its test fails when the game uses something it leaves out), in its own hashed chunk, so an update that changes only game code keeps Phaser's file. The dev server and Vitest load the package's own bundle.
- **Portrait:** on a touch screen in portrait, the kit's turned page frame (`view/frameTurn.ts`, `view/frameTurnLandscapeGame.css`, imported by `src/main.ts`) turns the game page's frame (the nav column and the game) onto its side to fill the screen, and moves the safe-area insets onto the frame's turned edges as `--inset-*`. It turns 90 degrees clockwise, read with the phone turned counter-clockwise, or -90 where the screen reports portrait-secondary (upside down). `src/input/frameTurn.ts` watches the turn. Touches map through it (the kit's `pageToGame`), and the kit's `followFrameTurn` has Phaser measure `#game`'s own size, leave the canvas's placement to `src/main.css` and map its pointers the same way. When the browser turns to landscape, the frame is unturned.
- **Rooms:** a door is an instance whose archetype is `door`, with a `room` from `ROOMS` (`src/data/rooms.ts`); the resolver refuses a door without a room and a room on anything else. Use at it holds the zone still and plays the door's `open` tag (its character's `animations.open`, else the tag named `open`) where its art has one, for as long as the tag runs (`src/view/doorOpen.ts`); then `ZoneScene` launches `RoomScene` and pauses, so the pause button hides and P, Escape, back and a frame turn leave the pause card shut. `RoomScene` hides the zone and fills the whole canvas with ink: the room's backdrop, or a PLACEHOLDER frame, its animations and cast, its name centred, and Leave at the view's top right (`src/layout/roomScreen.ts`), art's `ui-button` with `ui-focus` round it under keyboard focus. Leave, back and Escape close it (`src/pause/roomInput.ts`); Tab and the arrows focus Leave, and Enter and Space press it. The zone resumes with her at the door as she was, the door closed again (its idle tag), with no key or touch held. A room changes no save, so reopening the game mid-room opens the map with her on that zone. A room's `enter` and `shop` are typed but not built.
- **Save data:** progress uses the kit's versioned save in `localStorage` under `duck-platformer.save`. It stores completed stage-node ids and the selected stage, and loads after `launchReady` before the first screen appears. Invalid, incompatible or older progress is backed up under `duck-platformer.save-backup` and resets; a future version is left alone. Before version 1.0, format or id changes bump the save version and reset older data without migration. Saved progress opens the map; no save opens the start screen. Restart confirms first, then clears only progress. The separate version-3 `duck-platformer.stats` save resets older clock data without migration and stores active seconds by catalogue stage id, survives map/title/reopening and progress restarts, and resets a stage's clock on every clear. Physics steps accumulate in memory, with one-second checkpoints and immediate flushes on pause, death, exit and page lifecycle events. Menus, dialogue, death presentation and retry-card time do not count. Where storage is unavailable, saves last only for the page session. Settings keep their own keys. Developer `?zone=` routes bypass the progress save.
- **Scenes:** `BootScene` runs first: it loads everything `public/art/manifest.json` lists and makes an animation of each sprite tag, keyed `<sprite>:<tag>`, with the tag's frames and durations from the sprite's Aseprite export. A tag the sprite's manifest entry lists in `once` plays once and holds its last frame; every other tag loops.
- **Security headers:** the build writes `dist/_headers` from `src/headers/securityPolicy.ts`: a Content-Security-Policy per page with its inline blocks hashed, and a year's caching for hashed build output under `/assets/`.
- **Settings card:** the pause card's Settings row opens `SettingsScene` in the pause card's place over the same dim, and the start screen's Settings button over the start screen (`src/layout/settingsCard.ts`): the Move controls and Action buttons rows, the Install row while the game can be installed, and the build label. The scene that opens it passes it the keys and back, and gets it back when it closes. Install shows the browser's install prompt, or the install steps card in the settings card's place. The close X, P, Escape and back close the card on top, back to the scene that opened it; Tab and the arrows move the keyboard's focus and Enter and Space press. Each setting is kept in `localStorage` under its own key (`src/settings/touchControls.ts`). Move controls shows the move hint and Action buttons shows Use and Jump, both on by default; hiding either hides only its drawing, and movement and the button presses still work. A player who hid the old single Touch controls setting starts with both hidden.
- **Shared kit:** `@andornaut/game-kit` is a committed copy at `vendor/game-kit/`, synced by game-kit's `scripts/sync-into.sh` with its source commit in `vendor/game-kit/KIT_COMMIT`, and changed only at its source.
- **Start screen:** Start and Continue use the shared dslate primary face with white text, without a play mark; Restart uses the grey secondary face. With a save, Restart sits on the left and Continue on the right; Continue remains the default keyboard action and first focus target. Their buttons share standard 48px height and matching widths, with an 8px gap when paired. The game opens on `StartScene` (`src/layout/startScreen.ts`) unless progress is saved (Save data): Start opens the map with her on the first zone; once progress is saved, Continue (in Start's row, beside Restart) opens the map where she stands (Save data), under a nav bar with Settings, which opens the settings card, and Exit at its right end. Behind them is zone 1's street, dimmed two steps down each colour's ramp as the pause card dims the zone: `ZoneScene` draws it once as a paused, input-free backdrop without the duck or the touch buttons, the start screen reads that frame back from the canvas, and the dimmed texture is kept for later visits. Exit, and back with no card open, leave through the kit's `exitApp`: an installed app closes its window, and a browser tab goes to the site's home page. Back with the settings card or its install steps open closes them. An installed app whose window a script cannot close (the kit's `appCannotClose`, read in `src/pwa/index.ts` as the page loads: every app but Chrome's on Android and Chrome's and Edge's on desktop, or one whose history holds more than the game's entry) shows no Exit, Settings takes the right end, and back there is the browser's own. Tab and the arrows move art's focus ring through Start, Settings and Exit, as on the pause, settings and install steps cards, and Enter and Space press the focused one (Start with nothing focused).
- **Test helpers:** `src/testing/` is importable only from tests.
- **View:** `src/view/` picks each sprite's tag and whole-pixel position from the game state, Phaser-free, so the scenes only draw what it picks.
